# CLAUDE.md: working on the ShipKit repo

> Rules for AI agents (and humans) editing **this repository**. These are not the rules ShipKit installs into users' projects. Those live in `framework/master_prompt.md` and are installed by `npx shipkit-africa init`.

## What this repo is

| Surface | What it is | How it's verified |
|---|---|---|
| `framework/*.md` | **The product.** Prompts and guides read by AI agents in users' projects | Manual review (see checklist). Nothing verifies them automatically |
| `registry/` + `registry.json` | 17 shadcn-installable components (`lib/shipkit/*`, `components/shipkit/*`) | `typecheck/`: `npm run typecheck` + `npm test` |
| `r/*.json` | Built registry items served by GitHub Pages | Generated by `npx shadcn@latest build -o r`. Never hand-edit |
| `cli/` | The `shipkit-africa` npm package (zero dependencies) | `cd cli && npm test` |
| `typecheck/` | Compiles every component against app shims, and unit-tests pure helpers | Itself |
| `index.html`, `assets/` | Docs site at https://biyinzikabruce.github.io/shipkit-africa/. `index.html` is generated by `python3 scripts/build-site.py` from `registry.json`. Edit the script, not the HTML | The script asserts its groups match `registry.json`; then open it in a browser and run the link check |

## Non-negotiables

### Framework docs (`framework/`)
- **Accuracy over completeness.** Every API, header, endpoint or config option must match the provider's **current official docs**. Verify before writing. If unsure, describe the pattern and link the official docs instead of guessing specifics.
- Only link to pages you have opened and confirmed.
- Every `shipkit/...` path mentioned must exist in an installed project. `planning/templates/*` are installed to the project root, not under `shipkit/`.
- Keep the security rules intact: `input: false` on privilege fields, server-side `requireRole` + scoping, Decimal money, verified and idempotent payments.
- Write original content in plain, direct English.

### Components (`registry/`)
- Each component is one file. Imports between components use `@/lib/shipkit/*`, and app imports use `@/lib/auth`, `@/lib/auth-client`, `@/lib/prisma`, `@/lib/utils`, `@/components/ui/*`.
- `import "server-only"` at the top of anything that uses secrets, the database or Node APIs.
- `"use client"` only where needed. Never on a module that reads a non-`NEXT_PUBLIC_` env var.
- Effects clean up everything: timers, listeners, `AbortController`.
- **Fail closed:** missing session, organisation, secret or signature → deny or throw, never allow.
- No TypeScript parameter properties (`constructor(public x)`): tests run in Node's strip-only mode.
- Every new or renamed component updates **all of:** `registry.json`, `framework/components.md` (with TRIGGERS), `cli/bin/shipkit.mjs` `COMPONENTS`, the README tables, and the `GROUPS` list in `scripts/build-site.py` (then re-run it). Then rebuild `r/`.
- Don't edit `typecheck/shims/**` to silence a real error. Fix the component.

### CLI (`cli/`)
- Zero runtime dependencies (it runs via `npx`).
- `cli/framework/` is generated by `scripts/bundle.mjs`. It's gitignored, so never edit or commit it.
- `init` must never overwrite a user-edited file without `--force`, and must keep user content outside the `<!-- shipkit:start/end -->` block.
- Adding an agent = `src/agents.mjs` + tests + both READMEs + the docs site.

- [ ] Changed `cli/`: `cd cli && npm test`, and `npm pack` then install the tarball in an empty folder and run `npx shipkit-africa init`
- [ ] Changed the site: every link works, and it looks right at 360px and desktop
